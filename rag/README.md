# RAG 语义检索模块

在原有的「结构化提取」之外，另建一条**语义检索**通道：不只是把要点提出来，
还能用一句自然话，从整份招标文件里把相关原文找回来并作答。

```
可以.docx
   │ 01_切块.py        切成 400 字/块（段落级重叠 1 段）
   ▼
可以_chunks.json       409 块
   │ 02_向量化.py      bge-m3，1024 维
   ▼
可以_vectors.json      409 个向量
   │ 03_RAG问答.py     多查询扩展 + 混合检索 + 生成
   ▼
带出处标注的回答
```

---

## 三个脚本

| 文件 | 作用 | 跑一次要多久 |
|---|---|---|
| `01_切块.py` | docx → 小块的 JSON | 几秒（不花钱） |
| `02_向量化.py` | 每块 → 1024 维向量 | 约 1 分钟（花 embedding 额度） |
| `03_RAG问答.py` | 提问 → 检索 → 生成回答 | 每次提问调 1 次 embedding + 1 次 LLM |

**只需要在第 2、3 个脚本里填一个硅基流动的 Key。**
DeepSeek 的 Key 会自动从 `%APPDATA%\投标决策助手\config.json` 读取（和主程序共用）。

---

## 检索做了哪四件事

### 1. 多查询扩展（治「列举型问题」检索不到）

问「废标条款有哪些」时，自动扩展成 6 个查询：

```
废标 / 否决投标 / 投标无效 / 不予受理 / 取消投标资格 / 视为放弃
```

各取前 5 名，合并去重。因为这类问题的答案散在十几个块里，
**没有任何单独一块像「废标条款有哪些」这句话**。

### 2. 关键词混合检索（治覆盖率不足）

纯向量检索在「列举型问题」上召回不够，所以补一条字面检索通道：

```python
LIST_KWS = ["废标", "否决投标", "投标无效", "不予受理", "取消投标资格",
            "视为不参加投标", "视为放弃", "不予接收", "拒绝接收",
            "将被拒绝", "不接受", "不予退还", "不得参加投标", "取消中标资格"]
```

命中这些词的块**全部追加进候选**，不受前 8 名截断限制。

### 3. 来源优先级（治「正文盖过补充通知」）

招标文件的补充通知会覆盖正文条款，但向量只算语义相似度，不懂谁更新。

- 检索层：含「补充通知/补充说明」的块 +0.05 加权
- 生成层：提示词明确「冲突时以补充通知为准，并指出原条款已被修改」

> 实测：正文写保证金 80 万，补充通知改为 100 万 —— 系统正确采用了 100 万，
> 并提示「原正文/表格条款已被补充通知修改」。

### 4. 相似度阈值兜底（防硬编）

```python
MIN_SCORE = 0.55   # 最高相似度低于此值 → 判定「库中无相关内容」，拒绝作答
```

问「天气怎么样」时返回：

```
⚠️ 没有任何块的相似度超过阈值 → 库中没有相关内容
```

**宁可说不知道，也不编一个看起来合理的答案。**

## 实测表现

| 提问 | 结果 |
|---|---|
| 最高投标限价是多少 | 8600 万元，注明补充通知未修改该项 ✅ |
| 投标保证金什么时候交 | 100 万元（指出正文 80 万已作废）；截止时间按投标截止顺延推断至 10月20日，并标注"此为推断非原文结论" ✅ |
| 废标条款有哪些 | 分四类列出 15+ 条，附出处；并主动声明「片段未呈现完整废标专章，可能遗漏」 ✅ |
| 项目经理需要什么资格 | 一级建造师 + B 证 + 无在建项目，逐条附出处 ✅ |
| 天气怎么样 | 拒答 ✅ |

## 已知局限

- **列举型问题覆盖率约 70%**：22 条废标条款能稳定召回 15-17 条。
  进一步要靠结构化字段过滤（把「废标条款」做成独立索引）而不是纯向量检索
- **来源标签靠文本匹配判断**：块里只要出现「补充通知」四字就被标为补充通知，
  对混合内容的块会误判。更稳的做法是建库时按原文卷章结构打 metadata
- **只支持已切块的单份文档**：跨文档检索需要把多份 chunks/vectors 合并成一个库

## 和主程序的关系

两套东西各管一段，互不依赖：

| 主程序（投标软件.py） | RAG 模块 |
|---|---|
| 把全文压成 9 大类要点 | 从全文里精准找回某几段 |
| 追求「零丢失」（106 条清单一条不少） | 追求「召回准」（该找到的能找到） |
| 输出 Word 报告 | 输出回答 + 出处 |

**不是替代关系，是两条腿。** 报告用来看全局，检索用来问细节。
